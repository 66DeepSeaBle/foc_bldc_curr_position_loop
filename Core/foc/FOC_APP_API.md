# FOC 应用层接口说明（给上层 MCU / 上位机 / PLC）

文件：`Core/foc/foc_app.h` / `foc_app.c`（实现在 `foc_control.c` 末尾）
适用固件：`2026-10-25 cal30 20k nogate B1`

---

## 0. 一句话总览

这个接口提供 **「角度定位」** 一件事，参数化两个旋钮：

| 旋钮 | 单位 | 含义 | 默认 | 范围 |
|---|---|---|---|---|
| **力矩档** | A | 位置环允许输出的最大 q 轴电流（**限幅**） | 2.50 | 0.30 ~ 5.00 |
| **速度档** | °/s（机械） | 定时轨迹的巡航速度（**上限**） | 800 | 10 ~ 1500 |

⚠ **重要语义**（不要误解）：

- **力矩档是"封顶"，不是"给定力矩"。** 实际电流由位置环算，空闲可以是 0 A，
  堵转时才会顶到档位。想要"恒定输出 X A"请用 `FOC_Control_SetTorqueProbe()`
  的探针接口（限时），本接口不提供持续力矩模式。
- **速度档是"这一趟走多快"，不是"转速目标"。** 到目标就是位置保持，不会
  以某个速度一直转。要持续转速需要另外做速度环模式（当前未提供）。

## 1. 初始化（必须首先调用一次）

```c
FOC_Control_Init(&g_foc, &config);   /* 底层先初始化 */
FOC_App_Init(&g_foc);                /* ★ 再调这个, 之后所有 FOC_App_* 才有效 */
```

`FOC_App_Init()` 把两个旋钮复位到默认值（2.50 A / 800 °/s）。
在任何 `FOC_App_*` 之前没调它，所有设置类函数都会静默失败。

## 2. 设置 / 读取旋钮

### 2.1 一次设两个

```c
typedef struct {
    float torque_a;      /* 力矩档(A),  <=0 表示"这一项不改" */
    float speed_deg_s;   /* 速度档(°/s), <=0 表示"这一项不改" */
} FOC_AppTuning_t;

FOC_AppTuning_t cfg = { .torque_a = 2.70f, .speed_deg_s = 800.0f };
FOC_App_SetTuning(&cfg);          /* 返回 1 = 已接受 */
```

### 2.2 单参数

```c
void  FOC_App_SetTorque(float amp);   /* 超范围自动夹到 0.30~5.00 */
float FOC_App_GetTorque(void);

void  FOC_App_SetSpeed(float deg_s);  /* 超范围自动夹到 10~1500 */
float FOC_App_GetSpeed(void);
```

### 2.3 派生量查询（调试用）

力矩档 X 安时，内部各项上限：

| 函数 | 含义 | 与 X 的关系 |
|---|---|---|
| `FOC_App_GetIqLimitDrive()` | 轨迹期**驱动方向**电流上限 | 基准 1.70 A，掉队时才放开到 X |
| `FOC_App_GetIqLimitTrim()` | 位置微调上限 | `0.80 × X` |
| `FOC_App_GetIqLimitDamp()` | 阻尼项上限 | `0.32 × X` |
| `FOC_App_GetIqLimitKick()` | 破黏脉冲电流 | `0.80 × X` |

> `drive` 从 2026-10-25 起**不再随 X 等比放大**：固定基准 1.70 A，只有
> 跟踪误差超过 10° 才按 `(X − 1.70)` 线性放开，35° 时放到 X。
> 原因：drive 跟着 X 放大会让起步冲过头；太小又推不动深齿槽。

## 3. 移动命令

### 3.1 主接口

```c
uint8_t FOC_App_MoveTo(float target_deg, float speed_deg_s, float dur_s);
```

| 参数 | 说明 |
|---|---|
| `target_deg` | 目标机械角度。**多圈、可负**（例：`7200.0f` = 20 圈）。限 `|target| < 100000` |
| `speed_deg_s` | 本次巡航速度。`<= 0` ⇒ 用当前速度档 |
| `dur_s` | 本次总时长。`> 0` ⇒ **时长优先**，忽略 `speed_deg_s`；`<= 0` ⇒ 按速度反算时长 |

返回值：`1` = 已接受并启动；`0` = 参数非法 / 未初始化 / 读数上已在目标上。

三种典型用法：

```c
FOC_App_MoveTo(180.0f,  0.0f, 0.0f);   /* 按当前速度档走到 180° */
FOC_App_MoveTo(0.0f,  600.0f, 0.0f);   /* 这一趟用 600 °/s */
FOC_App_MoveTo(90.0f,   0.0f, 1.5f);   /* 这一趟限时 1.5 s */
```

### 3.2 预估时长

```c
float FOC_App_EstimateTime(float dist_deg, float speed_deg_s);
```

$$ T = \max\left(\frac{1.8\,D}{v},\ \sqrt{\frac{12.7\,D}{a_{max}}}\right),\quad T \ge 0.20\,\text{s} $$

- `D` = `|dist_deg|`，`v` = 给定速度（≤0 用速度档，且被速度档夹住）
- `a_max` = 加速度上限，**随速度档等比缩放**：`a_max = speed_deg_s × 10`
- `D < 1°` 返回 `0`（视为已在目标上）

含义：短行程被加速度限制、长行程被速度限制。两者相等时
$D \approx 3.92\,v^2/a_{max}$；默认档（800 °/s, 8000 °/s²）约 **314°**。
⇒ **行程短于 314° 时，调速度档的效果会被加速度吃掉一部分。**

### 3.3 到位 / 故障查询（轮询）

```c
float   FOC_App_GetPos(void);     /* 当前机械角度(多圈, 可负) */
uint8_t FOC_App_Arrived(void);    /* 1 = 已在容差内并停稳(消抖 500ms 已过) */
uint8_t FOC_App_IsFault(void);    /* 1 = FAULT, 需重新标定 */
```

**推荐上层流程**：

```c
FOC_App_MoveTo(target, 0.0f, 0.0f);
while (!FOC_App_Arrived() && !FOC_App_IsFault()) { /* 等 */ }
if (FOC_App_IsFault()) { /* 处理故障, 重新标定 */ }
else { float pos = FOC_App_GetPos(); /* 用 pos 而不是 target! */ }
```

⚠ **用 `FOC_App_GetPos()` 而不是直接相信 `target`**：到位容差默认 **6°**，
实测目标 70° 会停在 73.34°、目标 360° 停 362.5°。原因有两个：
① 到位容差 6°（为匹配霍尔 15.47° 阶梯而放宽）；
② 转子最终停在一个**齿槽定位点**上，与目标的差值取决于齿槽相位。

## 4. 一段移动的客观指标（可选）

```c
uint8_t FOC_App_TakeMoveStats(int32_t *max_tv_mdeg,   /* 0.001° */
                              int32_t *max_iq_ma,      /* 0.001 A */
                              int32_t *band_ma,        /* 0.001 A */
                              int32_t *drive_ma);      /* 0.001 A */
```

读即清（返回 1 = 有新数据）。每段移动结束产生一次。

| 字段 | 含义 |
|---|---|
| `max_tv` | 本次最大跟踪误差（参考 − 实际） |
| `max_iq` | 本次最大 `|Iqref|` |
| `band` | 当时的力矩档 |
| `drive` | 本次**用过的最大**驱动侧上限（随误差变化，报峰值） |

判据：
- `max_iq ≈ drive` 且 `max_tv` 很大 ⇒ 驱动权限不够，加大力矩档
- `max_iq < drive` 明显 ⇒ 不是权限问题

## 5. 硬件链路参数（只读）

```c
typedef struct {
    float shunt_ohm;    /* 采样电阻 = 0.010 Ω */
    float amp_gain;     /* 运放增益 = 8.0 */
    float v_per_a;      /* = shunt × gain = 0.080 V/A */
    float a_per_lsb;    /* 12bit/3.3V 下 = 10.07 mA/LSB */
    float v_zero;       /* 零电流电压 ≈ 2.112 V */
    float range_pos_a;  /* 正向可测 = 14.85 A */
    float range_neg_a;  /* 负向可测 = 26.4 A */
} FOC_AppHw_t;

uint16_t zero_counts = /* 从 [ADCR] 的 offU 取, 例 2616 */;
FOC_AppHw_t hw;
FOC_App_GetHw(zero_counts, &hw);
```

> **增益为什么只能 ×8**：零电流偏置 2.112 V 若用 ×16 变 4.22 V > 3.3 V，
> 运放/ADC 直接饱和。×8 已是该偏置下的最大可用增益。
> **5.0 A 上限为什么不是 6.0 A**：过流保护按相电流峰值判 6 A，
> 留 1 A 余量。

## 6. 运行时按键（调试用，非正式接口）

| 键 | 作用 |
|---|---|
| `]` / `[` | 力矩档 ±0.1 A |
| `}` / `{` | 速度档 ±20 °/s |
| `0`~`9` | 走到数字 × 45°，固定 0.9 s 轨迹（自动启动/标定） |
| `z` | 走到 0° |
| `t<角度> [d<秒>]` + 回车 | 定时轨迹移动（顺序、大小写、分隔符随意） |
| `A` | 到位后关 PWM（静默保持）开关 |
| `v` | 详细日志（25 ms） |
| `w` | VOFA 波形开关 |
| `r` | 重新标定 |

> **关于「精度模式」：已移除。** 曾有 `E` 键把到位容差 6° → 1°，试图做 ±1°
> 定位；实测 `tag 20k A2c` 证明**物理上做不到**：齿槽周期 15°，稳定平衡点在
> 73.34°，目标 70° 落在两个齿槽之间的斜坡上，要按在那里需持续 ≈1.9 A 对抗
> 齿槽弹簧，而近目标可用电流只有 0.8~1.30 A ⇒ 顶不动。强行放开限幅会立刻
> 引发 73.34° ↔ 55.65° 的粘滞-滑移振动。
> ⇒ **定位精度 = 一个齿槽内的残差（实测 1.8~3.4°）**，这是机构极限。

## 7. 已知限制（重要）

1. **上限**：目标角度 `|target| < 100000°`；跑飞保护为"指令距离 + 3600°(10 圈)"，
   且每个新目标/空闲 500 ms 后会按当时误差自动重设门槛。
2. **速度档上限 1500 °/s 只是软限**，实际受加速度上限与齿槽牵引能力约束。
   实测齿槽能擒住的上限约 **195 °/s**（自由停车时），带轨迹时可达 750 °/s。
3. **最短行程**：`FOC_App_MoveTo` 对 `D < 1°` 视为已到位，不启动轨迹。
4. **到位精度 ±3.4°**：转子最终停在最近的齿槽平衡点，`|err| < arrive_tol(6°)`
   即撤力。想更准只能改硬件（编码器）；软件上唯一可行的做法是**把目标吸附到
   最近的可达齿槽点**，而不是硬顶。
4. **没有真正的力矩模式 / 速度模式**。当前只有位置环。
5. **多圈绝对值依赖霍尔计数**，上电必须标定（ALIGN）一次；标定后原点会被重置。
